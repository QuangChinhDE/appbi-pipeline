SOURCE: source-base-project (Base Project Public API)

DESCRIPTION:
Reads services, service metadata, projects, boards, groups, tasks and task activity from extapis.base.vn/project/v1. Requires an acting user (user_id: numeric id or username without @).

IMPLEMENTED STREAMS:
- service | POST service/all (page, 200) | full refresh, incremental (client-side)
- service_field | POST service/get.fields | full refresh
- service_item_type | POST service/get.itemtypes | full refresh
- service_stage | POST service/get.stages | full refresh
- project | POST project/list (page, 200) | full refresh, incremental (server updated_from)
- project_board | POST project/get.boards | full refresh, incremental (client-side)
- project_group | POST project/get.groups | full refresh
- task | POST task/list (per project, include_archived) | full refresh, incremental (client-side)
- task_activity | POST task/get.activity (per task, keyset before, 100) | full refresh, incremental (client-side, global cursor)

APIS NOT YET CONVERTED TO STREAMS:
- task/get.comments | no sample data in test workspace (32/32 empty)
- project/get, service/get, task/get | same fields as list APIs
- ping, sysinfo | technical
- 8 write APIs | out of scope

CURRENT STREAM LIMITATIONS:
- all | data limited to what user_id can see | changing user_id changes results
- task | task/list has no updated filter | every sync reads all projects' tasks
- task_activity | one call per task; no event id (composite key) | request volume; same-second identical events merge
- task_activity | full refresh config logs "Could not find cursor field" warnings | warning only, data complete

GENERAL LIMITATIONS:
- Documented host api-v3.{domain} does not work on base.vn; extapis is used.

NOTES:
- Auth: X-API-TOKEN header (extapis.<domain>/{app}/v1, POST JSON). Body status=0 fails the sync.
- Incremental cursor is always chosen by the user; no default cursor.
- Detailed Vietnamese notes, test runs (2026-10-22) and API-team requests follow below.

2. HẠN CHẾ CỦA TỪNG STREAM
-------------------------
Chung
  - Dữ liệu và giá trị custom field (cfields) phụ thuộc quyền của user_id.
    Đổi user_id có thể làm thiếu hoặc thừa dữ liệu.
  - Phân trang page/limit (tối đa 200): đã đo 20 task với 3 task mỗi trang,
    không trùng, không sót. Chưa thấy lỗi mất bản ghi như Sales, nhưng dữ liệu
    test còn nhỏ.
service
  - API không có bộ lọc: incremental lọc phía client, mỗi lần sync đọc lại
    toàn bộ (số lượng nhỏ).
service_field / service_item_type / service_stage
  - Gọi một lần cho mỗi service; không có cột thời gian nên chỉ full refresh.
  - service_field.options là array; chưa có mẫu để khai báo cấu trúc phần tử.
project
  - Lọc server bằng updated_from (gửi một mốc là đủ). Giữ thứ tự mặc định
    (mới tạo trước), KHÔNG dùng sort_by=updated&sort_order=asc như tài liệu
    gợi ý. Lý do: với phân trang theo page, sắp theo thời gian cập nhật làm
    record vừa sửa trong lúc sync dời ra cuối, đẩy các record khác lùi một vị
    trí và làm sót bản ghi.
  - Project đã lưu trữ (status -1) đã có sẵn trong danh sách mặc định.
  - start_date và deadline thường bằng 0 nên không dùng làm cursor.
project_board
  - Lọc phía client; board được tạo cùng lúc với project nên trùng giây,
    incremental đọc lại nhiều.
project_group
  - Không có cột thời gian; chỉ full refresh.
task
  !!! task/list KHÔNG lọc được theo thời gian cập nhật (đã thử updated_from,
      updated_at_from, last_update_from; đều bị bỏ qua). created_from lọc được
      nhưng không bao trùm khi cursor là updated_at hoặc finished_at, nên chỉ
      lọc phía client: mỗi lần sync vẫn gọi task/list cho mọi project.
  - Gửi include_archived=true để lấy cả task đã lưu trữ (mặc định API bỏ qua).
task_activity
  - Gọi một lần cho MỖI TASK ở mỗi lần sync (API không có bộ lọc thời gian).
    Workspace nhiều task sẽ tốn nhiều request.
  - Event không có id; khóa chính ghép (task_id, at, action, user_id). Chưa
    gặp trùng trong 73 event, nhưng về lý thuyết hai thao tác giống nhau trong
    cùng giây sẽ bị gộp làm một.
  - Dùng một cursor chung cho cả stream, state lưu dạng ISO (giống
    job_detail của BPM).
